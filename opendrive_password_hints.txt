OpenDrive needs its own database role on the Supabase instance created by
this repo. That role is described in opendrive_role.sql (create once, after
the postgres container first boots).

The password for opendrive_app is NOT the same as POSTGRES_PASSWORD.
Store it as a separate GitHub Actions secret:

  OPENDRIVE_APP_PASSWORD = <32+ random bytes, hex or base64>

Injection point during a live session (after the runner boots and supabase
has started):
  docker compose exec -T db psql -U postgres -v OPENDRIVE_APP_PASSWORD="$OPENDRIVE_APP_PASSWORD" -f /path/to/opendrive_role.sql

DATABASE_URL for the OpenDrive API (Phase 1 reads this at startup):
  postgres://opendrive_app:<OPENDRIVE_APP_PASSWORD>@<supabase-host>:<POSTGRES_PORT>/postgres

For the self-hosted GitHub Actions runner, <supabase-host> is localhost
and <POSTGRES_PORT> is whatever KONG_HTTP_PORT-style port the workflow
exposes for Postgres (typically 5432, published from the db container).
